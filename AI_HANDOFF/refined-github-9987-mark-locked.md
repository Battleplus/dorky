## Goal

Add a list-page visual marker for locked issues/PRs. Refined GitHub already has:

- `locked-issue`, which marks the individual conversation page;
- `mark-pinned`, which replaces the list icon for pinned issues;
- `mark-merge-commits-in-list`, which is suggested by the issue as a likely structural reference.

The issue explicitly prefers a lock marker/icon on issue lists and says an icon before the title was already explored in #9663 and did not work well.

## Reference implementation

Current `source/features/mark-pinned.tsx` observes:

```ts
observe('a[data-testid="issue-pr-title-link"]', mark, {signal});
```

and replaces the existing issue icon while preserving the list container. Use this pattern as the starting point rather than inserting another icon before the title.

Also inspect the current `locked-issue` implementation to reuse the same lock icon, CSS conventions, and lock detection semantics where possible.

## Design

Preferred behavior:

- on repository issue/PR list pages, a locked item gets a lock marker in the existing icon/status area;
- no background highlight is required;
- pinned behavior must not be broken—define deterministic precedence if an item is both pinned and locked;
- open/closed/PR state must remain understandable, so do not blindly destroy useful status semantics;
- avoid per-row network calls.

Choose the smallest implementation based on current DOM. If GitHub already renders a lock indicator or accessible state somewhere in each row, derive from it. If lock state is only available through already-fetched page data, reuse that. Do not introduce an API fan-out across every row.
